# AI 異常検知システム (PatchCore / PaDiM)

**バージョン**: 0.0.10

---

## このプログラムについて

このプログラムは、**カメラと PatchCore / PaDiM AI（異常検知アルゴリズム）を活用し、製品の傷・汚れ・異物・欠損などの異常を自動判定する検査システム**です。

正常な状態の画像特徴（メモリバンク）と比較することにより、事前学習された正常パターンから外れる製品を即座に「異常（NG）」として検出します。物体検出（YOLO等）とは異なり、良品データのみから高精度な異常検知を実現します。

---

## 主な機能

1. **PatchCore アルゴリズムによる異常検知**
   * バックボーンネットワーク（ResNet等）から抽出した高次元特徴マップとメモリバンクとの距離を計算し、異常スコアを算出。
   * 設定されたしきい値（Threshold）に基づき、高精度かつリアルタイムに OK / NG 判定を実施。
   * インクリメンタル判定付きバースト撮影に対応し、複数枚撮影時の効率的な確定処理をサポート。

2. **ハードウェア・GPIO連携**
   * **外部トリガー入力**: センサーや PLC からの GPIO 信号を検出して自動撮影・検査を実行。
   * **パターン切り替え**: セレクターピン（ビット組み合わせ）により、品種やワークに応じた検査パターンを自動切替。
   * **制御出力**: 判定結果（OK / NG）に応じたパトライト点灯やブザー制御（保持・自動OFF等に対応）。

3. **証拠画像・CSVログの保存**
   * 判定結果（OK, NG, NG_RAW, SKIP, REC）をそれぞれの解像度設定に従って自動保存。
   * 日々の検査結果（スコア、パターン名、カメラ名、判定結果）を CSV ファイルに自動記録。

4. **Windows モックモード対応**
   * GPIO 非搭載のPC（Windows 等）で起動した場合は「仮想 GPIO パネル」が動作し、実機なしで機能確認・テストが可能。

## 動作フロー

```
起動
  │
  ├─ 設定ファイル読み込み (inspection_settings.json)
  ├─ 結果フォルダの生成 (results/)
  ├─ PatchCore モデルのロード
  ├─ カメラのオープン・プレビュー開始
  └─ GPIO (または仮想GPIO) の初期化
          │
          ▼
  [トリガー待機ループ]
  トリガー信号受信
          │
          ▼
  セレクターピン確認 → 実行パターンの決定
          │
          ▼
  バースト撮影（画像取得）
          │
          ▼
  PatchCore 推論（異常スコア算出 ＆ しきい値比較）
          │
          ▼
  判定結果に応じて GPIO 出力 / ブザー鳴動
  画像保存 (results/images/) ＆ CSV 追記
          │
          ▼
  サイクル完了 → コミット番号更新、次のトリガーへ
```

## ユーザー操作ガイド

### 1. 正常学習用画像の収集
* 画面上部の「撮影モード」を切り替え、正常品の画像を収集します。
* 収集した画像は **パターン・カメラ・トリガーの組み合わせごと** にサブフォルダへ自動振り分けされ保存されます（`results/images/REC/{パターン名}_{カメラ名}_{トリガー名}/`）。
* 収集した良品画像から学習済みモデルを作成します。

### 2. 詳細設定
画面右下の「**詳細設定**」ボタンから各項目を設定します。

| タブ | 設定内容 |
|---|---|
| システム設定 | プレビューFPS、バースト撮影回数、表示時間、前後分割判定モード、微小欠陥検査設定 等 |
| カメラ設定 | 使用カメラの選択・解像度・プレビュー設定 |
| GPIO設定 | トリガーピン・セレクターピン・出力ピンの割り当て |
| パターン設定 | パターンごとのモデルパス・判定しきい値の設定（前後分割対応時はFr/Rr別の判定条件） |

### 3. 検査実行
* 画面上部の「検査モード」を有効にします。
* 外部トリガー待ち状態となり、トリガー信号を受信すると自動判定を行います。
* 前後分割判定モード時は、1台に対して `0001 Fr` → `0001 Rr` の順に検査が進行し、整数時（Fr）にのみパターンを取得して両工程で同一パターンを引き継ぎ判定します。

## 結果フォルダ構成

```
results/
├── images/
│   ├── OK/          # OK判定画像
│   ├── NG/          # NG判定画像
│   ├── NG_RAW/      # NG判定時の元画像
│   ├── SKIP/        # SKIP判定画像
│   └── REC/         # 撮影モード保存画像
│       └── {パターン名}_{カメラ名}_{トリガー名}/   # 組み合わせごとに自動フォルダ分け
├── csv/
│   └── inspection_results_YYYYMMDD.csv   # 日別判定ログ
└── logs/
    └── app_YYYYMMDD.log                  # 動作ログ
```
